# Приорбанк: прямое подключение без файла · 19.10.2026

**Предыдущий компьютерный этап.** Основная кнопка в FinApp теперь использует [серверное подключение](prior-server-connection.md), работающее без локального помощника. Описанный ниже loopback/popup остался диагностическим кодом и больше не является рабочим мобильным потоком.

Реальный вход и совпадение показанных сумм уже подтверждены владельцем. Обязательная промежуточная выгрузка удалена из основного пути: помощник передаёт выбранную карту и операции прямо в FinApp. Старый файл поддерживается как необязательный запасной способ.

## Как пользоваться

1. На компьютере запустите `Start-Prior-Preview.cmd` (Node.js 24+); помощник должен оставаться запущенным.
2. Обновите рабочий FinApp и откройте «Банки» → «Приорбанк» → «Подключить Приорбанк». При блокировке окна разрешите его для FinApp и повторите нажатие.
3. В открывшейся локальной форме введите логин/пароль Prior Online, получите историю, выберите одну карту BYN и нажмите «Передать выбранную карту в FinApp».
4. Окно закроется после подтверждения получения. В FinApp появятся исходные операции; выберите счёт, проверьте категории, совпадения, начальный остаток и итог, затем добавьте выбранные записи.

Данные не сохраняются в журнале при входе или передаче. Правила действующего [пилота импорта](prior-import-release.md) сохранены: одно окно до 31 дня, завершённая история, проверка неоднозначных совпадений и неизменности уже импортированных дней. Доступная сумма банка не меняет начальный баланс FinApp. Телефон и постоянное фоновое обновление пока не поддерживаются; отдельное банковское право «только чтение» не подтверждено.

## Передача

- Сервис FinApp создаёт случайный 256-битный token, открывает только `http://127.0.0.1:5188/connect` и слушает конкретное открытое окно. Token/origin передаются в fragment, удаляются через `history.replaceState` и не отправляются HTTP-серверу.
- Разрешены только точный рабочий origin и явно перечисленные localhost origins для разработки. Обе стороны проверяют origin, source, token, version и структуру. `postMessage` всегда использует точный targetOrigin. Данные принимаются только после ready/ack; payload — ограниченная строка JSON со строгим существующим парсером. Лишние поля/секреты отклоняются.
- Передаваемый объект строится явно из разрешённых финансовых полей. Логин, пароль, банковские токены, полный банковский ID, доступный баланс и дополнительные неизвестные поля не передаются. Новых записей localStorage/sessionStorage нет; Supabase Auth остаётся в существующем клиенте и не участвует в мосте.
- Только `/connect` использует COOP `unsafe-none`, чтобы сохранить opener для обмена. Обычный `/` сохраняет `same-origin`; CSP, запрет iframe, no-store, точный Host, Origin/локальный capability и отсутствие CORS остаются. Нет удалённого API для входа в банк.
- Отсутствие помощника (30 секунд), окончание ожидания входа (10 минут), закрытие/блокировка окна и отмена объясняются в FinApp. Отмена, unmount и смена пользователя/семьи удаляют слушатель, закрывают окно и отвергают поздние ответы. Повторяются только сообщения ready, банковский вход автоматически не повторяется.
- После строгой проверки FinApp подтверждает получение, помощник закрывает окно и очищает просмотр. До подтверждения сохранения операции находятся в памяти страницы. Схема базы, RLS, RPC и финансовые расчёты не менялись.

Протокол сверён с первичными браузерными справочниками: [postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) и [COOP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Opener-Policy). Рабочий сайт проверен перед реализацией: COOP/COEP не задан, совместимость opener отдельно проверена на HTTPS origin с искусственными ответами.

## Проверки

- `npm test`: 61 проверка всего приложения и протокола, включая подложный origin/window/token, неизвестные поля/секреты, данные до handshake, однократный приём, отмену, блокировку/закрытие окна и таймауты.
- `npm run test:prior`: 14 проверок. Обычный `/` изолирует opener; `/connect` сохраняет его, остаётся no-store/CSP/iframe-protected; неверные пути и удалённый POST не начинают банковских запросов.
- TypeScript/Vite/PWA build пройден, новых зависимостей нет. Прежнее предупреждение о размере основного JS сохраняется.
- Искусственный сквозной UI: FinApp demo 390/320 px → popup → локальная форма → выбранная карта/строки в реальном компоненте проверки. Исходные BYN/EUR суммы/комиссия сохранены; HTML в описании остаётся текстом, файловая кнопка в popup скрыта, пароль очищен, горизонтального переполнения нет.
- Отдельный HTTPS тест с реальным сервисом подключения: защищённый рабочий origin → HTTP loopback popup → подтверждение получения. Подставлены только искусственные ответы; `-0.01` сохранено, лишняя сессия/полный ID/баланс не переданы, storage пуст, runtime-ошибок и удалённых POST нет. Это не проверка авторизованного production UI или реальной записи в базу.
- Отмена/закрытие сохраняют прежний предпросмотр, новых банковских запросов нет. Ссылка с чужим origin без доверенного opener не показывает форму и удаляет fragment. Первое реальное получение через новый мост и выбранное сохранение остаются проверкой владельца.
