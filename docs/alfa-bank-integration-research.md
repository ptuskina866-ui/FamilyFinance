- Дата исследования: 03.10.2026
- Целевая платформа пользователя: iPhone (Safari / WebKit PWA)

## 1. Краткий вывод о реализуемости

| Критерий | Статус | Комментарий |
|---|---|---|
| **Наличие официального API** | **Подтверждено** | У Альфа-Банка Беларуси действует портал [Alfa Developer Hub](https://developerhub.alfabank.by/developerhub/) с каталогом API для физлиц (`partner.authorization.individual`, `partner.individual.accounts`). |
| **Стоимость использования Open API** | **Бесплатно (согласно FAQ банка)** | В официальном FAQ банка прямо зафиксировано: *«Какая взимается плата за пользование Open API? — Open API предоставляется бесплатно»* ([источник](https://developerhub.alfabank.by/developerhub/site/pages/faq.jag)). |
| **Техническая реализуемость протокола** | **Подтверждено** | Протокол OAuth 2.0 Password Grant описан в Swagger/WSO2; сетевой шлюз `developerhub.alfabank.by:8273` отвечает по HTTPS с валидным сертификатом. |
| **Доступ к песочнице (Sandbox)** | **Подтверждено** | Регистрация учетной записи на портале разработчиков и создание приложения с Sandbox-ключами для тестирования со статичными данными бесплатны и доступны разработчику. |
| **Промышленный доступ (Production) для физлица** | **НЕ ПОДТВЕРЖДЕНО (Неизвестно)** | Несмотря на заявленную бесплатность Open API, регламент банка требует оформления заявки, согласования с сотрудником и **заключения договора о предоставлении промышленного доступа**. Возможность заключения такого договора частным физическим лицом для персонального семейного PFM-приложения пока не подтверждена. |
| **Прямое обращение из браузерной PWA** | **Не рекомендуется / Требует бэкенда** | Для защиты `client_secret` от утечки в браузере и надежной обработки CORS/сетевых вызовов необходим промежуточный бэкенд-прокси (Supabase Edge Function или Cloudflare Worker). |

> [!IMPORTANT]
> **Главный вывод:** Следует четко разделять два факта:
> 1. **Банк официально заявляет бесплатность Open API.**
> 2. **Возможность получения промышленного доступа физическим лицом для личного семейного приложения пока не подтверждена.**
> До выяснения банком условий предоставления боевых ключей физическому лицу разработка должна ограничиваться изолированным Sandbox-прототипом.

## 2. Доступ к банковскому API Альфа-Банка

### 2.1. Официальный портал и инфраструктура
- **Официальный портал разработчиков:** [https://developerhub.alfabank.by/developerhub/](https://developerhub.alfabank.by/developerhub/)
- **Платформа:** WSO2 API Manager.
- **Шлюз API (Gateway):** `https://developerhub.alfabank.by:8273`
  - Сетевая проверка подтвердила доступность шлюза.
  - Действующий TLS-сертификат: выдан УЦ `HARICA DV TLS ECC` на имя `*.alfabank.by` (срок действия до 06.02.2027).
  - *Безопасность TLS:* сертификат GlobalSign из открытого плагина ZenMoney истёк в июне 2023 г. Отключать проверку TLS или зашивать устаревшие сертификаты в FinApp недопустимо.

### 2.2. Сервисы для физических лиц в каталоге банка
В каталоге портала Альфа-Банка официально опубликованы API для работы с данными частных клиентов:
1. `partner.authorization.individual` (v1.0.0) — первичная регистрация партнерского устройства и авторизация по протоколу OAuth 2.0 (Password Grant).
2. `partner.individual.accounts` (v1.0.0) — получение продуктов (`/products`) и выписки по операциям (`/statement`).
   - Swagger-спецификация: [https://developerhub.alfabank.by/developerhub/api-docs/admin/partner.individual.accounts/1.0.0](https://developerhub.alfabank.by/developerhub/api-docs/admin/partner.individual.accounts/1.0.0).
3. `partner.individual.products` (v1.0.0) — витрина доступных продуктов банка.

### 2.3. Условия доступа и тарифы
- **Информация о тарифах в официальном FAQ:**
  В разделе [«Как это работает — FAQ»](https://developerhub.alfabank.by/developerhub/site/pages/faq.jag) на вопрос:
  > *«Какая взимается плата за пользование Open API?»*
  >
  > Банк официально отвечает:
  > *«Open API предоставляется бесплатно.»*
- **Порядок предоставления доступа:**
  - **Тестовый доступ (Sandbox Keys):** генерируется самостоятельно в личном кабинете после регистрации учетной записи. Позволяет тестировать API со специальными тестовыми значениями (`personId="TEST"`, `login="API"`).
  - **Промышленный доступ (Production Keys):**
    - Для бизнес-клиентов банка («Альфа-Бизнес Онлайн») предусмотрено подписание заявления онлайн с использованием ЭЦП/СМС.
    - Для сторонних партнеров и приложений процесс включает подачу заявки, контакт с представителем банка и заключение договора о предоставлении промышленного доступа с предоставлением пакета документов.
    - Лимиты вызовов в режиме опытно-промышленной эксплуатации: 100 запросов в минуту на API.
    - **Открытый вопрос:** открыта ли процедура заключения договора для частных физических лиц (без статуса ИП или юрлица) с целью интеграции персонального семейного бюджета.

## 3. Процедура подключения по изученному протоколу

Анализ исходного кода плагина [ZenPlugins/src/plugins/alfabank-by](https://github.com/zenmoney/ZenPlugins/tree/master/src/plugins/alfabank-by) (коммит `16203fc43057da3abe3ca41a19ec0c56727b14cc`) и документации портала описывает следующую последовательность.

### 3.1. Этапы авторизации
1. **Генерация идентификатора устройства:**
   - Формируется `deviceId` (строка формата KSUID).
2. **Шаг 1: Первичная регистрация (POST /individual/1.0.0/registration/registration):**
   - Пользователь передает:
     - Для резидентов РБ: `personId` (личный номер паспорта, 14 символов) и `isResident: true`.
     - Для нерезидентов: `documentNum` (номер документа), `issueDate` (`YYYY-MM-DD`), `isResident: false`.
   - Банк отправляет SMS с кодом подтверждения на номер телефона, привязанный к клиенту в банковской системе.
3. **Шаг 2: Подтверждение регистрации (POST /individual/1.0.0/registration/confirmRegistration):**
   - Приложение генерирует новую случайную связку `login` и `password`.
   - Пользователь вводит код из SMS.
   - В банк передается: `{ sms, login, password, deviceId, approve: true }`.
   - Флаг `approve: true` фиксирует согласие пользователя на предоставление персональных данных партнерскому приложению.
   - *Примечание:* пара `login` и `password` не является паролем от интернет-банка пользователя — это выделенные учетные данные конкретной связки устройства и приложения с банком.
4. **Шаг 3: Получение токена (POST /token):**
   - Content-Type: `application/x-www-form-urlencoded`.
   - Параметры: `grant_type=password`, `username=login`, `password=password`, `client_id=...`, `client_secret=...`, `scope=accounts_individual`, `source=individual`.
   - Ответ банка: `{ access_token, token_type: "Bearer", expires_in: 900, refresh_token, scope: "accounts_individual" }`.
   - Время жизни `access_token` — 900 секунд (15 минут).
5. **Последующие синхронизации:**
   - Для получения актуального токена приложение может повторно вызывать `POST /token`, используя сохраненную пару логин/пароль связки.

### 3.2. Чтение счетов и операций
- **Счета (`GET /individual/1.0.0/accounts/products?type={type}`):**
  - Запрашиваемые типы: `account`, `deposit`, `card`, `credit`.
  - Ответ содержит список продуктов с балансом, валютой (`currIso`), номером счета и маской карты.
- **История операций (`GET /individual/1.0.0/accounts/statement`):**
  - Параметры: `objectId` (ID счета/карты), `dateFrom`, `dateTo`, `pageNo`, `pageRowCount` (50).
  - Поля ответа: `amount`, `operationAmount`, `status` (`hold` или исполнена), `title` (мерчант/описание), `description` (детали платежа, город, код MCC), `operationType`.
  - **Идентификация и дедупликация:**
    - В `converters.js` плагина поле `id` формируется как `apiTransaction.id || null`, что указывает на возможность отсутствия явного `id` в некоторых ответах банка.
    - Стабильность идентификатора, область его уникальности (в рамках счета или банка), а также поведение при переходе операции из статуса `hold` (блокировка) в окончательно исполненную требуют отдельной проверки на практике.

## 5. Совместимость с FinApp (PWA на iPhone) и архитектура

### 5.1. Сетевые особенности браузерной PWA
1. **CORS:**
   - В ходе проверки был выполнен прямой GET-запрос к корневому пути `https://developerhub.alfabank.by:8273/`, где заголовок `Access-Control-Allow-Origin` отсутствовал.
   - Поведение preflight-запросов (`OPTIONS`) для прикладных эндпоинтов `/individual/1.0.0/*` с заголовками `Origin` и `Authorization` на боевом контуре без авторизации не проверялось.
2. **Порт 8273:**
   - Браузеры (включая Safari/WebKit на iOS) технически не блокируют порт 8273 (он не входит в список заблокированных портов спецификации WHATWG Fetch). Однако нестандартные порты могут блокироваться внешними сетевыми экранами и корпоративными прокси.
3. **Безопасность Client Secret:**
   - Ключевой аргумент в пользу бэкенда: секретный ключ приложения (`client_secret`) категорически нельзя публиковать в клиентском коде PWA, так как он доступен любому пользователю через инспектор браузера.

### 5.2. Рекомендуемая архитектура

```
[ iPhone / Safari PWA ]
       │  (HTTPS, JWT сессия FinApp: auth.uid())
       ▼
[ Backend Proxy: Supabase Edge Function (Deno) ]
       │  - Доступен только аутентифицированному владельцу подключения
       │  - Хранит ALFA_CLIENT_ID и ALFA_CLIENT_SECRET в переменных окружения (Secrets)
       │  - Проксирует запросы на developerhub.alfabank.by:8273
       ▼
[ Шлюз Альфа-Банка: developerhub.alfabank.by:8273 ]
```

### 5.3. Модель безопасности учетных данных (Credentials)
- **Принадлежность подключения:** банковская связка принадлежит конкретному пользователю (`auth.uid()`). Изоляция на уровне домохозяйства (`household_id`) не заменяет проверку владельца подключения: только пользователь, создавший связку, имеет право на ее синхронизацию и управление.
- **Доступность секретов:** банковские ключи (`client_secret`), пароли связки и токены должны быть доступны **исключительно серверной части** и не отдаваться в клиентский браузер.
- **Расположение ключей шифрования:** ключи шифрования для защиты сохраненных данных должны храниться в защищенной среде исполнения сервера (Supabase Secrets / Vault), изолированно от пользовательских таблиц БД.
- **Хранение секретов связки:**
  - `personId` (личный номер паспорта): передается транзитно при первичной регистрации, **не сохраняется в БД**.
  - Сохранение сгенерированных логина и пароля связки в БД (в зашифрованном виде с RLS) рассматривается как один из возможных вариантов долгосрочной архитектуры, но **не является обязательным требованием для реализации Sandbox-прототипа** (прототип может хранить параметры сессии в памяти).
  - Хранение паролей связки или токенов в незашифрованном `localStorage` браузера недопустимо.

### 5.4. Оценка ресурсов бесплатного тарифа
- **Supabase Edge Functions (Free Tier):** лимит составляет **500 000 вызовов в месяц**, время исполнения до 150 с. При синхронизации 2 раза в день для семьи расход составит менее 0.1% лимита.
- **Cloudflare Workers (Free Tier):** лимит составляет **100 000 запросов в день** (3 млн/мес), что также с огромным запасом перекрывает любые сценарии личного использования.

## 8. План минимального Sandbox-прототипа

Цель прототипа — проверка сетевого обмена и UI предпросмотра на тестовом контуре банка без записи данных в БД.

### Этапы прототипа:
1. **Конфигурация тестового контура:**
   - Передача `ALFA_SANDBOX_CLIENT_ID` и `ALFA_SANDBOX_CLIENT_SECRET` в окружение Supabase Edge Function `alfa-sync`.
2. **Авторизация тестового пользователя в Edge Function:**
   - Инициация вызова `POST /individual/1.0.0/registration/registration` со значением `personId: "TEST"`.
   - Вызов подтверждения `POST /individual/1.0.0/registration/confirmRegistration` с `login: "API"`.
   - Обмен пары на тестовый токен `POST /token`.
3. **Получение тестовых счетов и операций:**
   - Запрос списка тестовых продуктов (`/accounts/products`) и тестовой выписки (`/accounts/statement`).
4. **Предпросмотр в UI (Preview Modal):**
   - Отображение полученных тестовых операций в интерфейсе модального окна.
   - Тестирование сопоставления категорий в памяти через `AlfaBankService.detectCategory`.
   - **СТРОГО БЕЗ ЗАПИСИ В РАБОЧУЮ БАЗУ ДАННЫХ:**
     - Любое автоматическое или ручное сохранение тестовых операций в рабочие таблицы `transactions` исключено.
     - Прототип функционирует исключительно в режиме чтения и отображения в памяти сессии.

### Критерии приемки прототипа (Definition of Done):
- [ ] Edge Function успешно выполняет тестовый OAuth-обмен с сервером `developerhub.alfabank.by:8273`.
- [ ] Тестовые счета и операции корректно транслируются в UI предпросмотра.
- [ ] Ни одна тестовая операция не записывается в рабочие таблицы базы данных.
- [ ] Банковские секреты не передаются в браузер и не сохраняются в незашифрованном виде.
- [ ] Сборка проекта `npm run build` проходит без ошибок.
