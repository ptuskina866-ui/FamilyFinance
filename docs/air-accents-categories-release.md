# FinApp · акценты и категории для Беларуси · 20.10.2026

## Изменения

По просьбе владельца «Воздух» получил небольшие цветовые ориентиры: синий в ключевых действиях/дневном ориентире/активной навигации, зелёный у поступлений/наличных, мягкий фиолетовый у накоплений. Белые поверхности и открытый баланс сохранены. Иконки в журнале и выборе категорий различаются по группе. Счета и важные планы имеют мягкую тонировку; график расходов использует тот же синий.

Добавлен 31 вариант к существующему справочнику:

- 20 расходов: Корона, ProStore, Белмаркет, Доброном, Копеечка; вейп и табак, доставка продуктов, доставка еды, топливо/АЗС, парковка, сервис авто, подписки, комиссии банка, почта/посылки, ремонт/стройка, дети, спорт, путешествия, игры/приложения, благотворительность.
- 11 доходов: премии/отпускные, самозанятость/ИП, продажа вещей, сдача в аренду, пенсия, пособия/выплаты, стипендия, проценты по вкладам, дивиденды, возврат покупки, денежные подарки.

Названия сетей проверены по официальным страницам: [Корона](https://korona.by/), [ProStore](https://www.prostore.by/), [Белмаркет](https://bel-market.by/), [Доброном](https://dobronom.by/), [Копеечка](https://kopeechka.by/). Это категории учёта, без логотипов, рекламы или рекомендаций покупок.

В добавлении операции есть поиск по категории или знакомому названию магазина: «вэйп / vape», «Капеечка / Kopeechka», «21 век», «Куфар», «Е-доставка», «Ozon», названия операторов и другие aliases. Поиск ограничен типом операции и при вводе ищет по всем его группам; смена группы очищает запрос. Выбранная категория не меняется от ввода запроса. Для доходов — три колонки с более длинными названиями; категории прокручиваются, не сжимая иконки и подписи. Добавлены сообщения об отсутствии результатов и пояснения для возврата покупки/собственных переводов.

## Правила и совместимость

Новые IDs добавляются к общему `CATEGORIES`, который используют запись, журнал, аналитика, редактирование, планы и импорт. Старые категории и сохранённые операции не переклассифицируются. Новые продуктовые категории `food-*` включаются в существующий общий бюджет еды без двойного расходования. Категории дохода сохраняют префикс `income-*`; действующие SQL-проверки уже поддерживают такие значения. `group/searchTerms/note` — дополнительные типизированные метаданные интерфейса. Миграции, изменение RLS/Auth, новые зависимости и рабочие финансовые записи не требуются.

В подсказках будущего импорта сначала определяется доход: зарплата или возврат с названием магазина больше не получают расходную категорию. Добавлены точные правила для части новых магазинов/сценариев. Остальные варианты доступны для ручного выбора, неоднозначные описания не объявляются достоверно распознанными. Исправлено совпадение «газ» внутри «магазин»; коммунальный газ и АЗС остаются разными сценариями. Эти изменения затрагивают предложение категории, не извлечение/округление/сохранение денег и не дедупликацию. Перед добавлением остаётся проверка пользователем.

Возврат покупки записывается как поступление по действующей модели cashflow; исходный расход автоматически не уменьшается. Это явно указано в форме. Для перемещения своих денег используется существующий перевод между счетами.
