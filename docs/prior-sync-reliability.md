# Надёжность синхронизации Приорбанка · 24.10.2026

## Исправления

Фоновый worker ожидал JSON от любого успешного RPC. PostgREST возвращает пустое тело, в том числе HTTP 204, для void-функций захвата/освобождения lease. Успешный захват ошибочно превращался в `network`, lease оставался до истечения, а повторное открытие экрана конкурировало с ним и показывало сообщение о входе. Теперь пустое успешное тело допустимо. Проверки воспроизводят настоящие пустые 204 и 200 вместо искусственного JSON `null`. Диагностика содержит только этап и код проблемы, без исходных ошибок, сессий или банковских данных.

Открытие раздела выполняет `view`: читает сохранённый снимок того же владельца/семьи, не обращается к банку и не занимает lease. Кнопка обновления выполняет `refresh`; если банк уже обновляется, доступна сохранённая история того же периода. При другом явно выбранном периоде она не выдаётся за запрошенную. Только новые `view`/`refresh` получают `syncState`; старые `sync`/connect сохраняют прежнюю строгую оболочку, совместимую с установленными PWA.

Видимый экран без активного выбора перечитывает кеш раз в 30 секунд. Это не запрос к банку. Неизменившийся снимок не сбрасывает выбранные строки и категории; фоновое чтение приостановлено во время выбора, загрузки файла и переключения карты. Разрыв подключения и истечение сессии сохраняют штатную очистку; прежний снимок другой семьи не возвращается.

Даты банковских записей с ISO-временем показывают исходный календарный день: второе время больше не приписывается. Вместо общего «Новых» отдельно показаны доступные для добавления и записи с неподтверждённым статусом. Последние имеют значок часов, нейтральную отсутствующую сумму счёта и исходную сумму ответа банка. Знак этой суммы не считается доказательством дохода/расхода. Возможное совпадение с ручной записью того же счёта/дня/суммы лишь поясняет ситуацию; в валютных операциях исходная валютная сумма не сравнивается с BYN-журналом.

Worker кеширует завершённые десять дней основной истории для совместимости ручного импорта и сохраняет дополнительные строки для отображения, включая текущий день. Дополнительный список не импортируется: его название не доказывает pending/settled/отказ. Уточнённые счётчики и подсказки не меняют финансовых правил, суммы или категории. Автоматический учёт сохраняет проверенную основную историю в журнале на главной; исходный список банка остаётся отдельным представлением.

## Рабочая проверка

В рабочем Supabase развернуты `prior-connect` v3 и `prior-auto-sync` v3. Схема, миграции, RLS, Auth и расписание не менялись. После устранения причины только существующему включённому владельцем подключению снят временный `network` backoff с соблюдением lease. Новые финансовые записи создал штатный opt-in worker, ручных исправлений журнала не было.

Native scheduled run успешно завершился в 21:02:02 UTC 23 октября / 00:02:02 Минск 24 октября, без issue. Ограниченная чтением проверка относящихся к сообщению владельца записей подтвердила корректное направление автоматического зачисления и отсутствие автоматического дубля ранее внесённого ручного расхода. Исходные реквизиты, описания и банковские payloads в отчёт не включены.

Это подтверждает работающий фоновый путь, но не измеряет задержку банка. Проверка выполняется каждые две минуты при исправной сессии; ошибки используют прежний backoff. Мгновенные события не подключены. Срок банковской сессии, полнота истории и переходы дополнительных строк в основную историю остаются внешними ограничениями; изменения даты/суммы не имеют гарантированного stable ID. Физический Safari и установленная PWA после этого исправления ещё не проверены.
