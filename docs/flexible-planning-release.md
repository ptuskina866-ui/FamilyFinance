# Гибкое планирование: ближайшее дополнение FinApp

Реализованы принятые пункты ближайшего релиза: гибкие бюджеты, шаблоны зарплаты, подушка и фонды будущих расходов. Визуальный стиль сохранён; новых npm зависимостей для приложения нет.

## Возможности

- «Планы → Бюджет»: перенос непотраченных денег между категориями. Общий и свободный остатки сохраняются. Превышенная категория получает всю новую сумму сверх уже понесённых расходов.
- Там же: изменение/отмена распределения текущего месяца. Перед подтверждением показан доступный возврат. Уже потраченные суммы остаются расходами; отмена не создаёт доход. История решения и компенсирующие движения целей сохраняются.
- Прошлый месяц: повторить общий план в пустом месяце, заново зарезервировать остатки в категориях, отложить их в цель или оставить свободными. Один подтверждённый выбор предотвращает повторное выделение денег. История прошлого месяца не меняется.
- Шаблоны зарплаты: фиксированные суммы и проценты, приоритеты вверх/вниз, несколько шаблонов, изменение и архив. Применение заполняет предварительный план. Денег хватает сначала на верхние правила; при нехватке ниже показываются уменьшенные суммы перед подтверждением.
- «Планы → Фонды»: подушка в месяцах необходимых расходов и фонды на страховку/ремонт/другие платежи. Создание, изменение, взнос, возврат и архив используют общий учёт целей.

Старые цели остаются обычными целями. Подушка требует подтверждённую месячную базу и 1–12 месяцев; подсказка из истории усредняет выбранные категории за три завершённых месяца, учитывает нулевые месяцы и предупреждает о возможной неполноте истории. Продуктовые магазины не считаются дважды при выборе общей еды.

Все распределения требуют явного подтверждения. Шаблон не выполняет банковский перевод и не применяет финансовые действия автоматически. Перед оплатой из фонда освободите необходимую сумму и запишите расход со своего счёта.

Отмена возвращает только текущее доступное резервирование. Если деньги уже потрачены, ранее освобождены или фонд архивирован, они не возвращаются повторно. Изменение плана сначала компенсирует доступные прежние резервы, затем финансирует новый план одной транзакцией. Ревизия и конкретный возврат сверяются сервером: изменение данных на другом устройстве требует обновлённого предварительного расчёта.

Отменённый доход можно распределить снова через изменение того же плана. Его денежную сумму можно исправить с общей проверкой доступных резервов; тип и дата остаются защищены, а удаление запрещено ради истории. Изменение распределений прошлых месяцев не входит в этот выпуск.

## Технические изменения и база

Основные файлы: `src/components/BudgetManagement.tsx`, `IncomeTemplates.tsx`, `FundsPlanner.tsx`, `BudgetPlanner.tsx`; `src/lib/flexiblePlanning.ts`; `src/AppContext.tsx`, `src/types.ts`, `src/screens/PlansScreen.tsx`; изолированное демо и новые тесты.

Миграция `supabase/migrations/20261013085847_flexible_planning.sql` создана через Supabase CLI и зеркально включена в `supabase_schema.sql`. Добавлены household-owned таблицы шаблонов, решений по месяцу и ревизий распределения, поля назначения фондов и статуса/ревизии плана. Для новых таблиц включены RLS, четыре политики семьи, индексы и Realtime; клиенту дано только чтение. RPC используют блокировку household и явную проверку семьи. Внутренние функции находятся в закрытой схеме `finance_private`.

13 октября 2026 года перед установкой сделан частный снимок текущих операций, целей, счетов, бюджетов, распределений и изменяемых функций: `docs/sql/backup-before-flexible-planning.sql`. Проверка после установки подтвердила сохранение всех существующих финансовых строк. Новые планы/фонды не созданы за пользователя. `finance_schema_version`, `finance_planning_version` и `finance_flexible_planning_version` возвращают 1 для совместимости установленных клиентов.

Рабочая публикация подтверждена: [PR #5](https://github.com/ptuskina866-ui/FamilyFinance/pull/5), merge `896df49`, успешная сборка Cloudflare и версия `4f8709ee-3385-4295-a8bb-c612da76e699`. `index-B3_EbYgB.js` содержит новые инструменты; API версии отвечает 200/1 с ключом из опубликованной сборки, экран входа открывается без ошибок. Проверка выполнена также в свежем браузерном контексте. После фонового обновления PWA уже открытой вкладке может потребоваться повторная загрузка страницы.
