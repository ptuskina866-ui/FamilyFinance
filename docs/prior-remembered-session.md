# Приорбанк: запомненное подключение · 19.10.2026

Владелец подтвердил работу прежнего серверного подключения. Новый сценарий: один вход с согласием на сохранение банковской сессии, автоматическое получение истории при открытии раздела, выбор записей и одна кнопка добавления для уже связанного счёта. Прежняя версия сессию не сохраняла, поэтому после обновления нужен один новый вход.

## Поведение

- По умолчанию последние 10 **завершённых** дней по Минску (19 октября — 9–18 октября). Другой период до 31 дня доступен отдельно. Период относится к одной загрузке; старое ограничение суммарного диапазона пилота снято.
- Карта запоминается на сервере для пользователя. Связь карты со счётом сохраняется существующим атомарным импортом; единственная прежняя связь подставляется автоматически. Архивный/неподходящий счёт автоматически не выбирается. Несколько карт требуют первого выбора.
- Проверка выбранного счёта и квитанций импорта начинается автоматически. Уже загруженные строки скрыты, их можно показать. Категории остаются редактируемыми предложениями; спорные совпадения не выбираются массовой кнопкой.
- Первый импорт требует подтверждения счёта/начального остатка. Для уже связанного счёта выбор и нажатие «Добавить» подтверждают сохранение. Получение/просмотр сами по себе не создают проводок и не меняют баланс. Суммы/валюты не пересчитываются, свои переводы по-прежнему нужно исключать.
- Обновление при открытии раздела и вручную; фонового расписания нет. Частный финансовый ответ кешируется на 60 секунд, чтобы немедленное повторное открытие не вызвало повторный запрос банка/ограничение частоты. Показывается время фактического получения.
- Отключение удаляет серверную сессию/кеш, не удаляет финансовые записи. Серверная generation/CAS-проверка исключает восстановление подключения поздним ответом. Смена семьи сбрасывает сессию; каскадное удаление метаданных очищает секрет.

## Сессия и границы

Сохраняются только три непрозрачных поля банковской сессии в [Supabase Vault](https://supabase.com/docs/guides/database/vault), зашифрованные при хранении. Пароль, его хэши/соль и Supabase JWT не входят в сохранённый секрет. Пароль используется только для одного входа и очищается из полей/временных объектов; строки JS невозможно гарантированно обнулить в памяти runtime.

Приватная `finance_private.prior_connections`: owner + household, четыре RLS-политики, без grants клиентам. `prior_connection_state` вызывается только service_role после проверки пользователя через Supabase Auth; сервер использует verified user.id, не ID от клиента. В браузер возвращаются только финансовый whitelist и пять полей публичного статуса, без токенов, Vault ID, loginKey или revision. Логин для ограничения частоты хранится только как HMAC. Ключи сервера остаются штатными secrets Edge runtime.

Повторное получение использует только Cards/CardDesc, без Login/GetSalt/MobileToken. Подтверждённого механизма продления нет: [наблюдаемый клиент протокола](https://github.com/zenmoney/ZenPlugins/blob/master/src/plugins/priorbank/prior.js) при истечении сессии повторяет вход с паролем. FinApp пароль не сохраняет и такого повторного входа не выполняет. Поэтому обещание входа «навсегда» невозможно: при отказе/истечении сессии нужна новая авторизация пользователя. Сбой сети сам по себе сессию не стирает, автоматических повторов нет. Дополнительное банковское подтверждение и пароли длиннее 16 символов остаются неподдержанными.

## Повторные загрузки

Неизменённые записи пропускаются по прежним неизменяемым source/day/occurrence-квитанциям, даже после ручного удаления/изменения проводки. Новые скользящие периоды не требуют включать всю прежнюю историю. В пересекающихся сохранённых днях по-прежнему строго проверяется подпись всего полученного дня: изменение/исчезновение строки останавливает импорт.

Для похожей записи с другой датой (до 31 дня от сохранённой) добавлен сохраняемый отпечаток описания/знаковой суммы: сервер требует индивидуального подтверждения отдельной операции. Квитанция переживает удаление проводки. Исторические предупреждения заполнены из совпадающих по счёту/дню проводок; это может дать консервативные предупреждения для ручных записей. Настоящие повторные покупки не удаляются и не объединяются.

У ответа банка нет проверенного стабильного ID операции. Поэтому нельзя гарантированно сопоставить запись, у которой одновременно изменились дата/описание/сумма, или обнаружить перенос далеко за пределы сравнения. Предупреждение — повод сверить покупку, не доказательство дубля. Фактическая полнота банковской истории и переходы pending/settled остаются областью проверки владельцем. Сохраняются квитанции только дней с выбранными для добавления строками, не всех пустых дней.

## Проверки и публикация

- `npm test`: 63 проверки; `npm run test:prior`: 26; `npm run test:database`: шесть сценариев, 294 SQL assertions (71+41+64+58+20+40). Старая миграция тестируется как исторический контракт; новая — отдельно, включая полную/повторную схему, скользящие окна, изменение/исчезновение дня, сохранение квитанций после удаления, предупреждение/подтверждение реальной повторной покупки, права/RLS, CAS, смену семьи и очистку секрета.
- PGlite использует синтетический Vault adapter, не доказывающий шифрование. В рабочем Supabase отдельная проба с искусственным секретом проверила реальное шифрование/расшифровку; следующая проверила service-role save/load/disconnect и отказ запоздалого touch. Обе полностью откатились. Реальные банковские токены/пароли для этих проверок не читались.
- Рабочая миграция установлена, Edge `prior-connect` v2 ACTIVE, JWT verification=true. OPTIONS=204, отсутствующий/поддельный JWT=401. anon/authenticated не вызывают state RPC, не читают private/Vault; service_role EXECUTE=true, четыре политики. После проб таблица подключений пуста. Старая форма без action продолжает работать без сохранения сессии.
- 163 операции, один счёт, пять целей имеют те же построчные контрольные суммы до/после обновления. Security Advisor совпадает полностью кроме времени наблюдения: прежние 16 закрытых backup-таблиц, 20 финансовых RPC и настройка Auth; новых замечаний нет. Пояснения/ссылки прежних находок в `prior-server-connection.md`.
- `tests/prior-remembered-ui.js`: реальные компоненты и production transport/DTO parser в изолированном браузере с синтетическим API, React StrictMode, 320/390 px. Автозагрузка, подстановка счёта, скрытие добавленных, исходные BYN/EUR, HTML как текст, сохранение только выбранного, повторное открытие без login, истечение/новый вход, отмена ожидания/поздний ответ, отключение/очистка черновика, медленные счета и смена карты без наследования чужого счёта; runtime ошибок и переполнения нет. Это эмуляция Chromium, не физический iPhone/WebKit и не реальная длительность банковской сессии.
- TypeScript/Vite/PWA build пройден: `index-Hgz6sfc2.js`. Прежнее предупреждение размера основного bundle сохраняется. Проверка владельцем повторного открытия с реальной сохранённой банковской сессией остаётся после публикации.
