# Автоматический поиск регулярных расходов — 16.10.2026

## Что можно попробовать

- Главная → «Замечены повторения»; тот же блок в «Планы → Платежи».
- Два расхода в соседних месяцах — предварительная подсказка; три–шесть месяцев — более устойчивый наблюдаемый ритм. В рабочей базе сейчас есть история за сентябрь и октябрь, поэтому первая ступень полезна уже сейчас.
- Каждый вывод объясняется датами и суммами исходных операций. Видно изменение последнего платежа и предполагаемую следующую дату. Прошедшая дата не объявляется долгом: возможно, история не обновлена или услуга отменена.
- На главной можно открыть только исходные записи в журнале, затем вернуть все операции. Переключатель скрытия сумм действует и на выводы/историю внутри подсказки.
- Кнопка обновления открывает существующий импорт выписки. Автоподключение банка пока явно недоступно.

Подсказки ничего не записывают и не вычитают из доступных денег. Они не создают шаблоны, фактические расходы, новые категории, фонды или резервы. Уже настроенные пользователем регулярные платежи продолжают работать как раньше. Годовые/еженедельные ритмы, обучение категоризации, возвраты и автоматическое получение операций в эту версию не входят.

## Правила анализа

Данные берутся из существующего состояния текущей семьи, без дополнительного запроса чужих операций или внешнего ИИ. Группировка: точное нормализованное описание плюс счёт; номера магазинов и отделений сохраняются. Нужен один расход в каждом месяце подряд, даты отличаются максимум на четыре дня; для сравнения дни 29–31 ограничены 28-м. Следующая дата сохраняет день последнего платежа с ограничением длиной следующего месяца; если вся серия приходится на последний день месяца, прогноз также выбирает последний день. Наблюдение ограничено последними 12 месяцами; старые серии и будущие операции не используются. Трансферы, резервы/возвраты целей и созданные шаблоном операции исключены. Повтор строки с тем же ID игнорируется, несколько различных ID в месяце делают его неоднозначным. Суммы и разница считаются в целых копейках.

Вывод может пропустить платёж при изменяющемся банковском описании. Пара похожих операций может быть совпадением. Для известного шаблона требуется совпадение активного расходного шаблона, счёта и описания; совпадения категории недостаточно. «Последняя операция» описывает загруженную историю, а не время банковской синхронизации.

## Настоящее подключение банка

Кабинета Developer Hub и промышленного доступа у владельца пока нет. FAQ банка повторно проверен 16.10.2026. Условия доступа физлица остаются неподтверждёнными; Personal route относится к Альфа-Бизнес Онлайн. Подготовленный запрос и шаги: [исследование](alfa-bank-integration-research.md). Письма от имени владельца не отправлялись.

Клиентские `requestLogin`/`verifyOtp` возвращают явную ошибку вместо демоуспеха. Edge Function `alfa-sync` возвращает 503 с `ALFA_CONNECTION_NOT_CONFIGURED`; OPTIONS поддержан, другие методы получают 405. Она не читает тело с банковскими реквизитами, не вызывает банковские адреса, не генерирует тестовые счета/сессии/операции. Проверка JWT остаётся включённой. Официальные парсеры выписок не изменены. Предыдущая опубликованная версия функции сохранена локально в игнорируемом каталоге проверок.

## Проверки

- `npm test`: 50 проверок, включая 10 сценариев обнаружения и 2 проверки отказа неподключённого банка. Новый анализ проверяет точные копейки, разные счета, неоднозначность/дубли, будущие/неправильные даты, конец месяца/високосный год, предварительные выводы и неизменность исходной истории.
- `npm run test:database`: все 176 проверок существующих миграций проходят; схема и финансовые данные не менялись.
- Мобильная проверка: 320/390 px, раскрытие исходных операций, фильтр журнала/сброс, скрытие сумм и неизменность демо-данных при просмотре. Демо v4 содержит примеры подписки и интернета; старый ключ v3 не перезаписывается.
- `npm run build`: TypeScript, Vite и PWA проходят. Основной JS ~1.685 MB / 395 kB gzip; прежнее предупреждение о размере основного пакета сохраняется, новых зависимостей нет.

Сценарии после входа проверены в изолированном локальном демо; реальный вход пользователя и синхронизация нескольких устройств не проверялись в этой задаче.
