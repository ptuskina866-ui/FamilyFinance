# Приорбанк: локальный предпросмотр

Прототип подготовлен 19.10.2026 по разрешению владельца попробовать отдельное подключение на его компьютере. В рабочее приложение/базу ничего не записывает; счета, операции, категории и накопления FinApp не меняются.

## Как попробовать

1. Пока помощник запущен, откройте [локальную форму](http://127.0.0.1:5188/) на этом же компьютере.
2. Введите логин и пароль **от интернет-банка Prior Online**, выберите период (по умолчанию 7 дней) и нажмите «Получить счета и операции». Пароль вводится в локальной форме, не в чате.
3. Сверьте доступную сумму, валюты и несколько операций с Prior Online. Кредитный лимит показан отдельно; общая сумма по нескольким картам не складывается, поскольку они могут относиться к одному счёту.
4. «Очистить просмотр» удаляет показанные данные из страницы. Обновление/закрытие страницы также очищает просмотр. Для новой попытки пароль вводится заново; между попытками входа нужна минута.

Если помощник не работает, дважды откройте `Start-Prior-Preview.cmd` из папки проекта либо запустите `npm run prior:local`. Требуются установленные зависимости проекта и Node.js 24+. Закрытие окна помощника/остановка процесса отключает локальную страницу. Если порт 5188 занят, новый экземпляр не запускается и не подключается к неизвестному процессу.

Пароль длиннее 16 символов этот эксперимент локально отклоняет: он не обрезается, не отправляется в банк и менять его ради проверки не предлагается. Если банк требует дополнительное подтверждение входа, проверка остановится с сообщением; такой этап пока не реализован. Неверный вход, запрет или истечение сессии не запускают автоматический повтор. Коды банка и пароль не нужно присылать в чат; для разбора ошибки достаточно текста сообщения формы.

## Что показывает предпросмотр

- Карты с маской последних четырёх цифр, доступной суммой и отдельным кредитным лимитом.
- Историю связанного счёта: исходную дату/описание, подписанную сумму по счёту и отдельное поле суммы/валюты операции. Валюты не конвертируются и суммы не округляются.
- Дополнительный банковский список (`abortedTransactionList`) показывается отдельно, без догадки о статусе или направлении. Комиссия не прибавляется/не вычитается повторно, её валюта не предполагается автоматически.
- Идентичные строки отмечаются как возможные повторы, но ни одна не удаляется. Записи вне запрошенного периода остаются с предупреждением. Это **не готовый механизм дедупликации для импорта**.

Прототип не создаёт реальные расходы, переводы, категории, шаблоны или резерв. Не предоставляет экспорт банковских данных. Формат новых ответов должен быть проверен на реальном входе до проектирования импорта.

## Устройство и ограничения

`tools/prior-local/server.ts` слушает только `127.0.0.1:5188`. Host/Origin и секрет запроса, созданный при запуске, защищают локальный POST от других сайтов; нет CORS-доступа к API. Страница использует CSP/no-store и не загружает внешние ресурсы/аналитику. Данные запроса и ответа ограничены по размеру; запросы отменяются при закрытии страницы. Одновременные и слишком частые входы блокируются. Дополнительные локальные HTTP-пути и произвольные адреса банка не поддерживаются.

`bank.ts` отправляет запросы только к `https://www.prior.by/api3/api`: начальный обмен, challenge, вход, карты и история. Redirects запрещены; TLS-проверка не отключается. Логин/пароль, challenge-хэши и банковские сессии используются в памяти одной проверки и не записываются в файлы, localStorage, Supabase или журналы. Управляемые строки в памяти JavaScript нельзя гарантированно стереть физически; обещание касается отсутствия сохранения/логирования, а не криптографического обнуления памяти. Очистка формы не отзывает сессию на стороне банка; срок её действия определяет банк.

Используется обычный вход интернет-банка, отдельное банковское право «только чтение» не подтверждено. Ограничение на чтение реализовано набором запросов этого прототипа; платёжных методов в нём нет. Официальная публичная документация отдельного доступа к личным счетам не подтверждена. Изменение недокументированного интерфейса, дополнительная проверка входа и работа с конкретными картами остаются возможными препятствиями. Форму нельзя открывать с телефона через LAN: помощник намеренно привязан к этому компьютеру. Фоновая синхронизация и отправка в FinApp — будущая отдельная задача.

## Источники и независимость реализации

Сетевые поля/последовательность сверены с открытыми [prior.js](https://github.com/zenmoney/ZenPlugins/blob/master/src/plugins/priorbank/prior.js), [параметрами подключения](https://github.com/zenmoney/ZenPlugins/blob/master/src/plugins/priorbank/preferences.xml) и описанной структурой ответов. Последнее найденное изменение плагина — [12.06.2026](https://github.com/zenmoney/ZenPlugins/commit/64091639c9fbf431a773c4178ee4212f5773c5b6). Это свидетельство реализации, а не подтверждение текущей работоспособности личного подключения. Файлы/зависимости ZenPlugins в проект не включены; новый код написан отдельно на стандартных средствах Node.js. Тестовые ответы созданы искусственно и не содержат банковских данных владельца.

Для строгой проверки локального TypeScript добавлен только development-пакет типов `@types/node@24.11.0` (с `undici-types`); нового исполняемого пакета в мобильной сборке нет. Точная денежная нормализация использует существующий `src/lib/money.ts`.

## Проверено

- `npm run test:prior`: 13 проверок, включая протокол/порядок чтения, хэши challenge, отсутствие пароля в запросе к банку и секретов в предпросмотре, строгие суммы/даты/ответы, ошибочный вход без повтора, отмену, Origin/Host/секрет/размер запроса, конкуренцию и задержку повторов.
- `npm test`: все 50 проверок существующего приложения проходят.
- `npm run build`: TypeScript/Vite/PWA проходят; приложение сохраняет тот же `index-Ca_feLNw.js`. Сохраняется прежнее предупреждение о размере основного JS. Схема базы не менялась; повтор SQL-миграций для изолированного помощника не выполнялся.
- UI на искусственных ответах: 390/320 px без переполнения, пароль очищается, суммы/валюты показаны раздельно, сброс/ошибка работают, HTML в описании не исполняется, localStorage/sessionStorage пусты, runtime-ошибок нет.
- Реальный начальный запрос из Node к `MobileToken` вернул HTTP 200; логин, пароль и коды владельца для этого не использовались. Токены ответа не выводились и не сохранялись.

**Ещё не проверено:** реальный вход владельца, его карты/история, поведение дополнительного подтверждения, сроки банковской сессии, надёжность идентификаторов и границы исторических выгрузок. До пользовательской проверки это локальный эксперимент, не завершённое банковское подключение.
