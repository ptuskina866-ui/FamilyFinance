# Подтверждаемый импорт Приорбанка · 19.10.2026

Владелец подтвердил реальный вход, получение карт/истории и совпадение доступных сумм и сумм/валют нескольких операций с Prior Online. Следующий пилот переносит полученные операции в FinApp без повторного набора сумм и банковского пароля на сервере.

## Как попробовать

1. Запустите `Start-Prior-Preview.cmd` (Node.js 24+) и откройте `http://127.0.0.1:5188/`. Введите банковские данные только в локальной форме, получите историю и выберите **одну карту BYN**.
2. Нажмите «Подготовить файл для FinApp». Файл содержит маску карты и историю: сохраните его как банковскую выписку. Логина, пароля, сессии, полного номера/банковского ID и доступного баланса в нём нет.
3. В FinApp откройте «Выписка» → «Приорбанк», загрузите файл и выберите банковский счёт BYN. При необходимости сначала создайте отдельный счёт на главной. Его начальный остаток должен относиться к дате **до** выбранной истории; текущий банковский остаток не подставляется автоматически.
4. Нажмите «Проверить выбранный счёт». Это не создаёт ни операций, ни привязки. Уже загруженные строки недоступны для повторного выбора. Выберите новые операции; общая кнопка исключает спорные совпадения. Предложенные категории можно изменить.
5. Исключите собственные переводы и уже учтённые записи. Для одинаковых дат/сумм подтвердите, что это отдельные реальные операции. Проверьте изменение баланса, подтвердите счёт/остаток/категории и нажмите «Добавить выбранные операции».

## Границы пилота

- Одна карта/владелец на один банковский счёт BYN, одно окно до 31 дня. При повторном получении истории включайте **все ранее импортированные дни** карты. После выхода за пределы окна потребуется отдельная сверка и следующий этап интеграции.
- Загружается ненулевая сумма по счёту BYN с исходной датой/описанием. Валютная сумма покупки и комиссия показаны отдельно; они не прибавляются к списанию и не пересчитываются. Карты других валют остаются просмотром.
- Дата операции берётся из календарного префикса исходного банковского поля; дополнительный список, записи вне периода и день получения файла/более поздние дни недоступны для импорта. Старый файл, полученный посреди дня, не превращает этот день в полную историю на следующий день.
- Стабильные ID банка ещё не проверены. Поэтому ежедневные подписи включают все доступные строки и их количество, а также пустые дни. Изменение/исчезновение ранее импортированного дня останавливает загрузку. Самостоятельно исправлять банковские даты/описания в файле для обхода остановки не нужно.
- Отметки об импорте переживают редактирование/удаление операции в журнале. Повторная загрузка не восстанавливает намеренно удалённую запись и не отменяет ваши правки.
- Не проверены полнота истории, общие счета нескольких карт, дополнительные подтверждения/истечение сессии и постоянные банковские идентификаторы. Это подтверждаемый импорт, не фоновая синхронизация. Банковский пароль остаётся только в локальном помощнике.

## Устройство

`src/types.ts`, `src/lib/priorImport.ts`, `src/components/PriorImportPanel.tsx` и существующие AppContext/экран импорта. Парсеры Альфы и их форматы не менялись. Категории используют существующий `AlfaBankService.detectCategory`, без преобразования исходного банковского описания. Новых зависимостей нет.

Миграция `20261019095215_prior_reviewed_import.sql` отражена в `supabase_schema.sql`. Две таблицы `prior_import_sources`/`prior_import_days` имеют household_id, владельца, по четыре RLS-политики и клиентский доступ только SELECT. Источник закрепляется при первом подтверждённом сохранении. Публичные RPC проверяют текущую семью/владельца и используют общий финансовый lock; внутренний helper закрыт в `finance_private`. Сохранение выбранных операций и их отметок атомарно; ошибка откатывает всю попытку. Банковские сетевые вызовы/секреты в базе отсутствуют.
